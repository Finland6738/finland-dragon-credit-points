- M1-6: codec and guarded transport. `Net/Codec.lua` (adapted from Azeroth Accord): the text `<version>|<TYPE>|<payload>` with the payload as CBOR, deflated when that is shorter, in Base64, all through `C_EncodingUtil` via Compat; the version and the type are plain text, so a newer version or an unknown type is ignored without decoding (`PROTOCOL_NEWER` once per session), `Decode` never raises and returns a reason, required fields per type (`Codec:RegisterType`: the session protocol of M3 and the sync of M5 add their types; M1-6 only knows `HELLO`). The prefix carries the protocol version: `FDCP1`. `Net/Transport.lua` (adapted from Accord) sends over `RAID`, `GUILD`, `OFFICER` and `WHISPER` through ChatThrottleLib with the AceComm framing: priorities (ALERT, NORMAL, BULK), one message per gap on each distribution, a rate limit per type (`HELLO`: one per five minutes), the latest message per key wins, retries after a throttle result, and a queue that **waits** during a chat lockdown, an addon restriction **and a boss encounter** (`IsEncounterInProgress`), while the client refusing with a lockdown code is a wait, not a failure. A `RAID` message also waits while the character is not in a raid and is dropped after 120 seconds (a stale session message never reaches the next raid). Every message carries the guild key it was written for (`Config:GuildKey()`): it waits while the guild is unknown and is dropped if the character is in another guild by then. The waiting messages are saved in `FinlandDragonCreditPointsCharDB.outbox` at `PLAYER_LOGOUT` and queued again at `PLAYER_LOGIN` (without callbacks; expired, too old or damaged entries are dropped), so they survive `/reload`. The client's echo of the sender's own `RAID`, `GUILD` and `OFFICER` messages is counted and ignored; the first message or echo that arrives turns the feature `addonMessages` from `unknown` to `available` (spike S4). Incoming messages reach the rest of the addon only as the bus event `NET_MESSAGE(msg, sender, dist)`; sender names are never printed, stored or logged. `/fdcp debug` now also prints the transport and codec counters (any module can add lines with `FDCP:AddDebugSection`; English and Italian keys). `Tests/test_codec.lua` and `Tests/test_transport.lua` cover round trips, every malformed input, pacing, lockdown, restriction and encounter hold, keys, expiry, retries, the guild stamp, `/reload` and the saved queue, the receive path and the real ChatThrottleLib wire with multipart messages replayed to a second receiver.
- Not verified in game: that `RAID`, `OFFICER` and `GUILD` addon messages reach other members on WoW Forever with the prefix `FDCP1`, the real `Enum.SendAddonMessageResult` values and the throttling of ChatThrottleLib in a raid, that the lockdown and encounter hold match the client's real restriction timeline (spike S4), and that the saved queue survives a real `/reload`. - M1-5: locales and the no-text-in-code check. `Locale/Boot.lua` keeps every language in memory (AceLocale only keeps the client's), so `ns.L` follows the active language and texts for everyone can use the guild language: `Locale.Guild(key, ...)` (the `guildLanguage` setting now accepts any registered language). Adding a language is one file `Locale/<code>.lua` (it starts with `ns.NewLocale("<code>", "<name>")`) plus one line in each TOC. A missing key falls back to English, never an empty string; the client's `enGB` counts as `enUS`. The personal language (`/fdcp language [auto|code]`, stored in `FinlandDragonCreditPointsDB.global.language`) is read at setup and applied at the next `/reload`, because the client loads SavedVariables after the addon files. Number and date formatting follow the language (`Locale.FormatNumber`: "1,5" / "1.5" and thousands separators; `Locale.FormatDate`: `DATE_SHORT`, `DATE_LONG`, `DATETIME`), with the separators and patterns as keys of each language file. Command help is now looked up by key at print time (`helpKey`), so it follows the language. `tools/check_locale.py` (run by `check_docs.py`; it replaces the locale part of `check_addon.py`) fails on a missing, extra or unused key, different placeholders, a language not in the TOC, and hard-coded visible text in `UI/` and `Domain/` (a literal in `SetText`, `Print`, `AddLine`..., in a `text` / `title` / `label` field, or a two-word sentence; `-- nolocale` exempts a line), and tests itself with fixed cases. `Tests/test_locale.lua` runs the commands in both languages and checks key and placeholder parity, fallback, the override with `/reload`, the guild language, numbers and dates. README (EN + IT) has "Adding a language"; the wiki Commands page (EN + IT) lists `/fdcp language`.
- Not verified in game: that Italian and English clients show their language, that `GetLocale()` and the date patterns behave as in the mock on WoW Forever, and the language switch after `/reload`. The "in game" checkbox of M1-5 stays unticked. Not done: the whole existing suite is not re-run per language (many older tests assert English text); `test_locale.lua` runs every command in both languages instead.
- M1-4: Config, log, bus and guild key. `Core/Config.lua`: `FinlandDragonCreditPointsDB` through AceDB with profiles and defaults (guild language, roll seconds, debug), validated settings (`Config:Set` refuses unknown names, wrong types and out-of-range values with an error code), per-guild data under `db.global.guilds["<realm>/<guild>"]` so guilds never mix (key recomputed on guild and roster events, `GUILD_KEY_CHANGED` on the bus), a schema version with step-by-step migrations (`Config.Migrate`, a failing or missing step stops and keeps the last good version) and a read-only mode for a database written by a newer addon (no migration, no write, no new guild table, the version is never lowered); per-character data in `FinlandDragonCreditPointsCharDB`. `Core/Log.lua`: a 200-entry ring buffer with levels; entries store a code and arguments, and a string argument is printed as `<text>` unless marked `Log.Plain`, so debug output never shows names. `Core/Bus.lua`: internal events (`On`, `Off` by owner, `Emit` over a snapshot, failing handlers logged and skipped); Compat's `FEATURE_CHANGED` now reaches it. `Tests/test_config.lua` covers all of it, including `/reload` round trips.

- M1-3: Compat and capabilities. `Core/Compat.lua` (adapted from Azeroth Accord) is the only door to the game API: guarded calls (`Compat.Call`, a missing, raising or secret result never raises and is reported as `missing` / `error` / `restricted`), secret values never read, chat lockdown and addon restrictions, and one area per FDCP need: loot method, master looter and threshold (`C_PartyInfo.GetLootMethod`, the legacy `GetLootMethod` as a fallback), the loot window and master loot candidates (`GetLootSlotInfo` in both known shapes, `GiveMasterLoot`), `RandomRoll` and the roll and loot message patterns built from the client's own globals (`RANDOM_ROLL_RESULT`, `LOOT_ITEM*`, positional `%1$s` included), the instance and `IsEncounterInProgress`, `C_Item.*` info, item level, stats and stat delta, specializations (own and inspected), guild ranks, group roster, and the calendar (events and invites). `Compat:Probe()` fills an `available` / `missing` / `restricted` / `error` table per API and an `available` / `missing` / `unknown` state per feature (master loot, loot window, roll and loot messages, encounter state, item stats and delta, specialization, guild ranks, calendar raid, group roster, addon messages), run at login; modules refine a feature later with `Compat:SetFeature`. `/fdcp debug` re-probes and prints the table in chat without player, guild or item names (English and Italian). The mock client gained loot, rolls, encounters and restrictions (`Tests/mock/75_loot.lua`), items and specializations (`80_items.lua`), guild ranks and calendar (`85_calendar.lua`); `Tests/test_compat.lua` covers every area and a degradation sweep calls the whole surface with every API missing, raising and secret in turn, and all at once. Wiki: new Commands page (English and Italian). Names were checked against the Forever API dump: the globals `GetLootMethod`, `GetItemInfo`, `GetItemStats`, `GetItemInfoInstant`, `GetSpecialization*` and `GetGuildRankOrder` are not in it, so Compat prefers the `C_*` versions and keeps the globals as a marked fallback.

The "in game" checkbox of M1-3 stays unticked.
