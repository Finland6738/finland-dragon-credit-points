- M7-2b: automatic response labels (analysis §5.1, "Come è fatto (M7-2b)"; owner request of 2026-11-22). The optional label of a main-spec answer (BiS, big upgrade, small upgrade, situational) is no longer only a hand-picked chip: a new rule **`responses.labelMode`** of the guild's rules (new section `responses`, pure `Domain/Labels.lua`) says who picks it. **`suggest`** (the default): the addon fills the label in before the player answers and the player may change or clear it (a cleared label does not come back); **`auto`**: the addon sets it and the chips are locked; **`manual`**: the player, as before. The addon's choice is the data it already has: the item is on the player's best-in-slot list (M5-3) → BiS; else the main-spec verdict (M5-2) is a big upgrade → big upgrade, a small one → small upgrade; no upgrade, not comparable, not usable or no verdict → no label (situational is never suggested).
  - **Rule.** Validated by `Rules.Validate` (`responses.labelMode`), filled with `suggest` for rules written before (`Rules.WithDefaults`), a field of the Settings form on the **Priority** page (`RuleFields`), editable by the Guild Master only (M7-2's gate, open-season confirmation and audit unchanged) and frozen on the session at its opening like the other sections (`SessionFSM.LabelMode`).
  - **Popup.** `PopupBoard` gives the card `labelMode`, `suggestion`, `labelOrigin` and `labelHint`; `PB.Settle` and `PB.Pick` (pure, tested) decide what an answer carries; a line under the chips says who decides; off-spec, pass and the other tiers drop the label as before.
  - **Who chose it.** The response carries an origin `AUTO` (the addon's), `CHANGED` (the addon suggested one and the player picked another) or `MANUAL`, only with a label (`Domain/Reasons.lua` group `LABEL_ORIGIN`, English and Italian). The state machine keeps `item.labelOrigins` next to `item.labels`; the master looter's **Response** column reads "Main-spec · Big upgrade (auto)" or "… (changed)" (wider column) and the row tooltip says it in words; the board's candidates carry `labelOrigin`.

- M2-3: the event ledger. `Domain/Ledger.lua` keeps immutable events `{id, author, seq, ts, season, type, v, payload}`; the id is `author:seq`, unique per author, so a merge is a set union. `Ledger.Append` writes the author's next event (a void must reference an existing, voidable, not yet voided event), `Ledger.Merge` takes events in any order and any number of times (duplicates change nothing, a different event with the same id is reported as a conflict and the stored one wins, malformed events are refused with a code).
