### Added

- M2-5: rules, presets and rank permissions. `Domain/Rules.lua` is the configuration schema of `docs/ANALISI.md` §3 in sections (`night`, `members`, `season`, `cost`, `priority`, `session`, `council`, `legendary`, `bench`; the sections of M2-1 to M2-4 keep their own defaults and checks), with `Rules.Validate` (sorted `section.field` codes), `Rules.WithDefaults` (fills a missing section or key, never inside a key that is present) and `Rules.Diff` (the changed paths, for the audit); the rules live in the ledger as `CONFIG_CHANGED{rules, preset?, confirmed?}` carrying the whole validated configuration, and `Rules.Current(L, at)` gives the rules in force when an event was written. `Domain/Presets.lua`: `PATTO` (the defaults, §3.1), `ROLL_ONLY` ("Solo roll": highest roll, nothing costs credits), `LOOT_COUNCIL` ("Loot council puro": the council votes, nothing costs credits), `EPGP_SIMPLE` ("EPGP semplice": fewest credits per night played); `Presets.Match` and `Presets.Apply`. `Domain/Permissions.lua`: permission → lowest guild rank **index** (0 = GM), `config.rules` and `config.permissions` fixed at the GM, preset `season.manage` and `credits.adjust` for the GM and the rest for rank index 1 (officers), the table as `PERMISSIONS_CHANGED{table, confirmed?}`, one permission per ledger type (voids and manual corrections need `credits.adjust` outside a night, `night.run` in one). `Ledger.Append` and `Ledger.Merge` take a trust gate (`Permissions.Gate`): an event is accepted only if its author had the required rank when it was written, under the table in force then (a merge batch is applied in canonical order), a config event only from the GM (`NOT_GM`); otherwise `RANK_TOO_LOW` / `NOT_IN_GUILD`, or `PENDING` while the guild roster is not loaded (returned for the caller to queue). The rank at a time comes from a rank history (`RecordRank` / `RankAt`) the M3-1 adapter will keep, so a GM change hands over the config power and the old GM's changes stay valid; ranks are indexes, so renaming a rank changes nothing, and `RanksChanged` / `CheckRanks` report reordered, removed or added ranks to the GM. Rules and permission changes while a season is open need an explicit `confirmed` flag (`CONFIRM_REQUIRED`), kept in the event for the audit. `Season.Open/Close` and `Members.Join/LinkAlt` pass the gate on. Tests: `Tests/test_rules.lua`, `Tests/test_permissions.lua`.

- M2-4: seasons, members and late joiners. `Domain/Season.lua` reads seasons from the ledger: `Season.Open` writes `SEASON_OPENED{label?, instances = {{id, size}}, startCredits}` (the pack of instances, each 10, 20 or 40; `startCredits` from the configuration, preset 0, frozen in the event so a later configuration change never touches an open season), `Season.Close` writes `SEASON_CLOSED`; one season open at a time and an id is never reused (`SEASON_ALREADY_OPEN`, `SEASON_EXISTS`); after a merge the first opening of an id in canonical order counts and a close counts even when the officer's clock put it before the opening. `Season.CreditTable(season, instanceID, difficulty)` gives the season's one credit table for every instance of the pack, every size and both Normal and Veteran (`NOT_IN_PACK`, `DIFFICULTY` otherwise); `Season.NightCount` counts `NIGHT_OPENED`. `Domain/Members.lua`: `Members.Join` writes `MEMBER_JOINED{member, faction?, initialCredits, rule, basis?}`, `Members.LinkAlt` writes `MEMBER_LINKED_ALT{alt, main, faction?}`; only the declared main holds credits (`Members.Resolve` sends an alt to its main), a main is never an alt, a main and its alts share one faction, so a player on both factions has two mains with separate credits (`IS_ALT`, `ALT_IS_MAIN`, `ALREADY_LINKED`, `MAIN_UNKNOWN`, `FACTION_MISMATCH`); after a merge the first join and the first link count and a member wins over a link. Late joiners (`docs/ANALISI.md` §3.5): after the season's first night the initial credits are `average` (preset) | `median` | `min` | `zero` | `fixed` of the basis "members with at least N nights" (preset 1; the nights come from the lineup of M3, without them the whole pool), rounded `floor` (preset) | `round` | `ceil` to 0-2 decimals, written once in `MEMBER_JOINED` with the rule code (`START`, `AVERAGE`, `MEDIAN`, `MIN`, `ZERO`, `FIXED`, `EMPTY_BASIS`) and the basis size, so the value stays the same when the average moves, after voids, snapshots and merges. `Members.Roster` lists the pool by credits. The ledger now checks the payloads of `SEASON_OPENED`, `MEMBER_JOINED` (faction `Horde` / `Alliance`, rule code, basis) and `MEMBER_LINKED_ALT`. Defaults chosen where the analysis was silent (recorded in §3.5 and §6): a member is late once the season has an official night; with a declared faction the basis is the members of that faction (or without one); an empty basis gives the season's `startCredits`; the alt links belong to the season, like the declaration. `Tests/test_season.lua` covers opening and closing, the pack and the one credit table, mains and alts, merged conflicts, every late-join method and rounding, the night basis, factions and the stability of the initial credits. Real client: nothing to verify (pure Lua).
- M2-3: the event ledger. `Domain/Ledger.lua` keeps immutable events `{id, author, seq, ts, season, type, v, payload}`; the id is `author:seq`, unique per author, so a merge is a set union. `Ledger.Append` writes the author's next event (a void must reference an existing, voidable, not yet voided event), `Ledger.Merge` takes events in any order and any number of times (duplicates change nothing, a different event with the same id is reported as a conflict and the stored one wins, malformed events are refused with a code). Every event type of `docs/ANALISI.md` §8.3 is known, plus `SEASON_CLOSED`, `PROGRESS_SET`, `PERMISSIONS_CHANGED` and `LEGENDARY_PROJECT_OPENED` / `_PAID` / `_CLOSED`; payloads hold codes and numbers (reasons are codes like `WRONG_WINNER`, never sentences). Corrections are compensation, never deletion: `AWARD_VOIDED{ref, reason}` cancels an `ITEM_AWARDED` or a `CREDITS_ADJUSTED` and restores the previous credits, two voids of the same award count once, a void that arrives before its award still cancels it. Credits are computed: the first `MEMBER_JOINED{initialCredits}` of the member (canonical order: time, author, sequence) plus the costs of the awards to the member plus the adjustments, minus what is voided, rounded to 2 decimals; bank and disenchant awards move nothing. Snapshots (`Ledger.TakeSnapshot`, newest three kept) cover exactly the events up to the per-author high-water marks, so snapshot + tail always equals the full ledger, even when older events arrive later. For officer sync (M6): `Ledger.Heads` (contiguous high-water mark per author), `Ledger.Since(heads)` (what a peer lacks), `Ledger.Gaps`. Payload schema versions: older payloads are upgraded on read through `Ledger.UPGRADES` (the stored event never changes); an unknown type or a newer version is kept and forwarded for sync but ignored in the totals; a ledger table written by a newer addon opens read-only. `Ledger.FirstKills(faction)` gives the oldest date per encounter from `ENCOUNTER_KILLED` and `PROGRESS_SET` for the Progress export. `Tests/test_ledger.lua` covers append, merge, voids, adjustments, conflicts, versions, the sync helpers, snapshots and 25 random event sequences from three officers checked against an independent model (shuffled, batched, duplicated, snapshotted on the way). Real client: nothing to verify (pure Lua).
- M2-2: priority and the award proposal. `Domain/Priority.lua` is a pure function `Priority.Evaluate(state, config)` that replays the rounds held so far (responses, rolls in arrival order, credits, nights, presence, addon) with the algorithm of `docs/ANALISI.md` §3.4 and returns either the next round to hold (`ROLL` for a tier or a free roll, `REROLL` among the tied only) or the proposal `{kind, winner, response, tier, cost, credits, roll, reroll, rivals, reasons, flags}` with neutral reason codes (`MAIN_SPEC_TIER`, `OFFSPEC_TIER`, `TRANSMOG_TIER`, `LOWER_CREDITS`, `LOWER_CREDITS_PER_NIGHT`, `HIGHER_ROLL`, `REROLL_WON`, `ONLY_CANDIDATE`, `BOE_BANK`, `FALLBACK_DISENCHANT`, `FALLBACK_FREE_ROLL`, `FALLBACK_ML`, `TIE_ML`) and flags (`COST_BY_COUNCIL`, `DISCARDED_ROLLS`, `REROLL_LIMIT`, `TIE_UNRESOLVED`, `NO_BANK_CHARACTER`, `NO_DISENCHANTER`, `FREE_ROLL_EMPTY`), never sentences. Valid rolls only: 1-100, the first 1-100 roll of the player in the round, inside the round window, present, addon active, a candidate of the round; every discarded roll has a code. Metrics: credits (preset), credits per night, roll only; tie-breaks configurable (`roll`, `reroll`); tiers from the lowest, the next tier when a tier is empty; fallback: a BoE without main-spec goes to the bank (preset), otherwise the master looter decides (preset), disenchant or a free roll. The cost comes from the caller or from `Pricing.Price`. `Priority.Validate` checks the configuration. Defaults chosen where §3.4 was silent (recorded in §3.4): each tier has its own round; a roll with another range does not use the player's turn; a tied player who does not reroll forfeits, an empty reroll is held again, after five rerolls the master looter decides; zero nights count as one night; the fallback for non-BoE items is the master looter. `Tests/test_priority.lua` covers the regulation's three examples (ring: same credits, 76 wins; shoulder: fewer credits, 34 wins; cloak: tie on credits and roll, reroll between Bryn and Corin), off-spec only without main-spec, BoE to the bank, every discard code, the metrics, rerolls and the fallbacks. Real client: nothing to verify (pure Lua).
- M2-1: item classifier and pricing. `Domain/Classifier.lua` turns `classID` / `subclassID` / `equipLoc` (read by the adapter from `C_Item.GetItemInfoInstant`) into a cost category through editable tables (weapon, off-hand, trinket, quest, jewellery, armour, cosmetic, other); a quest item is the Quest class, an item that starts a quest, or an item in the season's token list; an item below the quality threshold (the group's loot threshold, blue by default) is not tracked. `Domain/Pricing.lua` resolves the cost in the order of `docs/ANALISI.md` §3.2: tracking gate, per-item override (`cost`, then `category`), the category × quality matrix of the "Patto" preset (cells may be decimals or `council`), then the response (MS × 1, OS × 0, transmog × 0), raid-size (10/20/40) and difficulty (Normal/Veteran) multipliers, rounded to two decimals; results carry codes, never sentences, and `Pricing.Validate` refuses negative costs and unknown categories. Defaults chosen where §3.2 was silent (recorded in §3.2): an override never brings an untracked item into a session; the multipliers apply to an overridden cost too; a missing cell (the "-" of the matrix, or green when the group lowers the threshold) goes to the council; off-spec on a council item costs 0; librams, idols and totems are priced as off-hand; shirts and tabards as cosmetic. `Tests/test_pricing.lua` covers every matrix cell, the classification rules, the threshold, the override order and the multipliers. - M1-6: codec and guarded transport. `Net/Codec.lua` (adapted from Azeroth Accord): the text `<version>|<TYPE>|<payload>` with the payload as CBOR, deflated when that is shorter, in Base64, all through `C_EncodingUtil` via Compat; the version and the type are plain text, so a newer version or an unknown type is ignored without decoding (`PROTOCOL_NEWER` once per session), `Decode` never raises and returns a reason, required fields per type (`Codec:RegisterType`: the session protocol of M3 and the sync of M5 add their types; M1-6 only knows `HELLO`). The prefix carries the protocol version: `FDCP1`. `Net/Transport.lua` (adapted from Accord) sends over `RAID`, `GUILD`, `OFFICER` and `WHISPER` through ChatThrottleLib with the AceComm framing: priorities (ALERT, NORMAL, BULK), one message per gap on each distribution, a rate limit per type (`HELLO`: one per five minutes), the latest message per key wins, retries after a throttle result, and a queue that **waits** during a chat lockdown, an addon restriction **and a boss encounter** (`IsEncounterInProgress`), while the client refusing with a lockdown code is a wait, not a failure. A `RAID` message also waits while the character is not in a raid and is dropped after 120 seconds (a stale session message never reaches the next raid). Every message carries the guild key it was written for (`Config:GuildKey()`): it waits while the guild is unknown and is dropped if the character is in another guild by then. The waiting messages are saved in `FinlandDragonCreditPointsCharDB.outbox` at `PLAYER_LOGOUT` and queued again at `PLAYER_LOGIN` (without callbacks; expired, too old or damaged entries are dropped), so they survive `/reload`. The client's echo of the sender's own `RAID`, `GUILD` and `OFFICER` messages is counted and ignored; the first message or echo that arrives turns the feature `addonMessages` from `unknown` to `available` (spike S4). Incoming messages reach the rest of the addon only as the bus event `NET_MESSAGE(msg, sender, dist)`; sender names are never printed, stored or logged. `/fdcp debug` now also prints the transport and codec counters (any module can add lines with `FDCP:AddDebugSection`; English and Italian keys). `Tests/test_codec.lua` and `Tests/test_transport.lua` cover round trips, every malformed input, pacing, lockdown, restriction and encounter hold, keys, expiry, retries, the guild stamp, `/reload` and the saved queue, the receive path and the real ChatThrottleLib wire with multipart messages replayed to a second receiver.
