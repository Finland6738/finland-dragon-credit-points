# M6 in-game checklist / Checklist in gioco di M6

This is the owner's check of milestone M6 ([`docs/roadmap/M6-history-export.md`](../roadmap/M6-history-export.md), step M6-8) in the real WoW: Forever client: **history, exports, the officers' ledger in sync, the credits read by every member, and backup**. A session cannot run the game, so every item below is **not verified** until the owner ticks it. Each item is written in English and then in Italian. It assumes [`M1.md`](M1.md), [`M3.md`](M3.md), [`M4.md`](M4.md) and [`M5.md`](M5.md) are done (a whole boss runs through the addon, and the council works from the window).

Questa è la verifica del proprietario della milestone M6 ([`docs/roadmap/M6-history-export.md`](../roadmap/M6-history-export.md), passo M6-8) nel client reale di WoW: Forever: **storico, esportazioni, registro degli officer sincronizzato, crediti letti da ogni membro e backup**. Una sessione non può avviare il gioco, quindi ogni voce qui sotto è **non verificata** finché il proprietario non la spunta. Ogni voce è scritta in inglese e poi in italiano. Presuppone fatte [`M1.md`](M1.md), [`M3.md`](M3.md), [`M4.md`](M4.md) e [`M5.md`](M5.md) (un boss intero gira attraverso l'addon, e il council lavora dalla finestra).

> Status / Stato: **checklist ready, owner run pending** / **checklist pronta, esecuzione del proprietario in attesa**.

Offline, the same story runs in `Tests/test_season_window.lua`, `Tests/test_history.lua`, `Tests/test_log_audit.lua`, `Tests/test_export.lua`, `Tests/test_site_export.lua`, `Tests/test_sync.lua`, `Tests/test_snapshot.lua` and `Tests/test_backup.lua` (the network simulator and the mock client). This checklist is the same story in the real client. / Offline, la stessa storia gira in `Tests/test_season_window.lua`, `Tests/test_history.lua`, `Tests/test_log_audit.lua`, `Tests/test_export.lua`, `Tests/test_site_export.lua`, `Tests/test_sync.lua`, `Tests/test_snapshot.lua` e `Tests/test_backup.lua` (il simulatore di rete e il client mock). ## 0. Before you start / Prima di iniziare

1. Run the offline checks from the repository root (they must be green). / Esegui i controlli offline dalla radice del repository (devono essere verdi):

   ```bash
   python -I -X utf8 tools/check_docs.py
   python -X utf8 Tests/run_tests.py
   ```

2. You need **three characters**: the **Guild Master** (who holds `season.manage`), an **officer** with the addon (who holds `export.public`, and runs a night of their own), and a **raider** or member with the addon who is **not** an officer. Use a test season id such as `M6TEST`, and close it at the end (section 10). / Ti servono **tre personaggi**: il **Guild Master** (che ha `season.manage`), un **officer** con l'addon (che ha `export.public` e fa una serata sua) e un **raider** o membro con l'addon che **non** è officer. Usa un id di season di prova come `M6TEST` e chiudila alla fine (sezione 10).

3. Record every result as `ok`, `fail`, `not tested` or `non provato`, with the build number from `/fdcp debug`. Never write character, guild or player names in the notes: write "Guild Master", "officer", "raider", "member". / Annota ogni risultato come `ok`, `fail`, `not tested` o `non provato`, con il numero di build di `/fdcp debug`. Non scrivere mai nomi di personaggi, di gilda o di giocatori nelle note: scrivi "Guild Master", "officer", "raider", "membro".
