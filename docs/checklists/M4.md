# M4 in-game checklist / Checklist in gioco di M4

This is the owner's check of milestone M4 ([`docs/roadmap/M4-loot-session.md`](../roadmap/M4-loot-session.md), step M4-9) in the real WoW: Forever client: **a whole boss handled by the addon**, from the kill to the last delivery. A session cannot run the game, so every item below is **not verified** until the owner ticks it. Each item is written in English and then in Italian. It assumes the checks of [`M1.md`](M1.md) and [`M3.md`](M3.md) are done (or at least their sections on loading, permissions, the night and the addon check).

Questa è la verifica del proprietario della milestone M4 ([`docs/roadmap/M4-loot-session.md`](../roadmap/M4-loot-session.md), passo M4-9) nel client reale di WoW: Forever: **un boss intero gestito dall'addon**, dall'uccisione all'ultima consegna. Una sessione non può avviare il gioco, quindi ogni voce qui sotto è **non verificata** finché il proprietario non la spunta. Ogni voce è scritta in inglese e poi in italiano. Presuppone fatte le verifiche di [`M1.md`](M1.md) e [`M3.md`](M3.md) (almeno le sezioni su caricamento, permessi, serata e controllo dell'addon).

> Status / Stato: **checklist ready, owner run pending** / **checklist pronta, esecuzione del proprietario in attesa**.

Offline, the same boss runs in `Tests/test_sim_boss.lua`: a raid of 40 on the network simulator (39 clients with the addon and one player without), every module real, with the boss's chat lockdown, a second lockdown in the middle of the answers, a raider's and the master looter's `/reload` in the middle of a round, a tie and its reroll, a `/roll` by hand from the player without the addon, master loot (plan A) and a trade (plan B). This checklist is the same story in the real client. / Offline, lo stesso boss gira in `Tests/test_sim_boss.lua`: un raid da 40 sul simulatore di rete (39 client con l'addon e un giocatore senza), tutti i moduli veri, con il lockdown della chat del boss, un secondo lockdown nel mezzo delle risposte, il `/reload` di un raider e del master looter a metà di un round, un pari merito e il suo reroll, un `/roll` a mano del giocatore senza addon, il master loot (piano A) e uno scambio (piano B). Questa checklist è la stessa storia nel client vero.

> **Season first / Prima la season.** A session opens only inside an **open season** (the session charges credits of that season). The Guild Master opens one from **Settings › Season** (section 0, step 5). It is written in the guild's ledger like any event and **cannot be deleted**, only closed: use a test guild if you do not want a test season in the real guild's history. Without a season the kill only says nothing (`NO_SEASON`): write `not tested` and why. / Una sessione si apre solo dentro una **season aperta** (la sessione addebita i crediti di quella season). Il Guild Master ne apre una da **Impostazioni › Season** (sezione 0, punto 5). Viene scritta nel registro della gilda come ogni evento e **non si può cancellare**, solo chiudere: usa una gilda di prova se non vuoi una season di prova nella storia della gilda vera. Senza season l'uccisione non apre nulla (`NO_SEASON`): annota `non provato` e il motivo.

## 0. Before you start / Prima di iniziare

1. Run the offline checks from the repository root (they must be green). / Esegui i controlli offline dalla radice del repository (devono essere verdi):

   ```bash
   python -I -X utf8 tools/check_docs.py
   python -X utf8 Tests/run_tests.py
   ```

2. Install the addon with a link (edits show after `/reload`). / Installa l'addon con un collegamento (le modifiche si vedono dopo `/reload`):

   ```bash
   python -I -X utf8 tools/fetch_libs.py
   python -I -X utf8 tools/install_addon.py --wow "<WoW folder>" --link
   ```

3. You need **three characters** in one raid: the **master looter** (the Guild Master, or an officer with `award.confirm` and `night.run`), a **raider** with the addon, and a **third raider without** the addon (or with it disabled). A second officer with the addon is useful for 3.8 (the read-only view). / Ti servono **tre personaggi** nello stesso raid: il **master looter** (il Guild Master, o un officer con `award.confirm` e `night.run`), un **raider** con l'addon e un **terzo raider senza** l'addon (o con l'addon disabilitato). Un secondo officer con l'addon serve per la 3.8 (la vista in sola lettura).

4. A boss you can kill that drops at least **two items at or above the loot threshold** (for example in Molten Core or Onyxia's Lair). For plan A the raid's loot method is **master loot** with the master looter set; for plan B see section 6. / Un boss che puoi uccidere e che lascia almeno **due pezzi sopra la soglia del loot** (per esempio in Molten Core o Onyxia's Lair). Per il piano A il metodo di loot del raid è **master loot** con il master looter impostato; per il piano B vedi la sezione 6.

5. Only if no season is open: the Guild Master opens a test season from **Settings › Season** (see [[Seasons|Seasons]]): picks Molten Core (40) and Onyxia's Lair (40), leaves the late-join rule, types the start credits, **Open the season** and **Confirm**. The ledger now has one `SEASON_OPENED`; the window shows the season and an officer's window shows it read-only. / Solo se nessuna season è aperta: il Guild Master apre una season di prova da **Impostazioni › Season** (vedi [[Season|Seasons-it]]): sceglie Molten Core (40) e Onyxia's Lair (40), lascia la regola di ingresso in ritardo, scrive i crediti iniziali, **Open the season** (Apri la season) e **Confirm** (Conferma). Il registro ha ora un `SEASON_OPENED`; la finestra mostra la season e quella di un officer la mostra in sola lettura.

   To close it at the end (section 8): **Close the season**, **Continue**, **Close it for good**. / Per chiuderla alla fine (sezione 8): **Chiudi la season**, **Continua**, **Chiudi per sempre**.

6. Record every result as `ok`, `fail`, `not tested` or `non provato`, with the build number from `/fdcp debug`. Never write character, guild or player names in the notes: write "master looter", "raider", "third raider". / Annota ogni risultato come `ok`, `fail`, `not tested` o `non provato`, con il numero di build di `/fdcp debug`. Non scrivere mai nomi di personaggi, di gilda o di giocatori nelle note: scrivi "master looter", "raider", "terzo raider".
